# Survey: Gsync/jobsync and DaKheera47/job-ops vs our job-apply engine

Method: read-only reading of the shallow clones under `.../scratchpad/up/{jobsync,job-ops}`. Nothing was run or installed. Paths below are relative to each repo root.

## Our engine, baseline (what "do we have it" is judged against)
Claude-driven skills plus Python tools, per-tenant folders. Discovery: LinkedIn via BrowserOS neo plus `tools/linkedin_harvest.js`, `tools/search_boards.py` (Greenhouse/Ashby/Lever slug lists from tenant `boards.json`), email job alerts, career-ops portal scan. Ledger CSV with fixed status and reason vocab, `coverage.py` miss counting, company files, truth-whitelist resumes via `make_resumes.py`, form filling with `ats-playbook.md`, `find_answer.py`/`learn_answer.py`, weekday read-only inbox follow-up and `log_outcome.py`, a read-only localhost dashboard (`dashboard.py`), `sync.py`. No numeric fit score, no scheduler beyond Claude scheduled tasks, no sponsor/visa data, no analytics funnel, no MCP server of our own, no freelance or contract source. `config/vocab.json` merely lists "contract" as a word.

## Best ideas (ranked for this person)
1. **Stored fit score plus "missing_or_unclear" brief per ledger row** (jobsync match directive + job-ops scorer). Add `fit_score`, `fit_reason`, `desc_quality` (title-only/partial/full) columns, scored by Claude itself in the existing review loop, using the first-line `SCORES:` convention. Provisional score when the description is a stub. Effort S, no new infrastructure.
2. **Deterministic pre-rank funnel with IDF weighting and per-run funnel stats** (jobsync `rank.ts`) in `search_boards.py`, so Claude only reads the top-K. Pair with job-ops **extractor health canaries** and jobsync **board-error notifications** so dead slugs and silent zero-result sources are caught automatically.
3. **Confidence-tiered email routing** (job-ops `email-router.ts`: >=95 auto-update, 50-94 review queue, <50 orphan or ignore) in `log_outcome.py`/follow-up. We currently trust the model's single call.
4. **Applied-duplicate detection** (similarity >=90 on normalised company and title within 30 days) and URL canonicalisation before id matching.
5. **Source analytics** (applications/day, funnel, response rate by source). Needs a `source` column and stage events; shows which feed (LinkedIn, ATS, alerts, freelance) actually returns replies.
6. **Job-fact patching with evidence quote** (job-ops): fixes salary/remote facts from scraped cards without guessing, consistent with our truth rule.
7. **Watchlist "new since baseline" + Workday adapter** (job-ops `career-boards/workday`), and jobsync's Lever/Ashby/Greenhouse `companies.json` as slug seeds.
8. **Freelance/contract gap (neither repo solves it).** Khamsat is Arabic, Egypt-only, and lists services sold by freelancers, not client briefs. Useful for us from these repos: Working Nomads and FreeHire keyless APIs (remote and contract tags), jobsync Contacts/Companies model for repeat clients, ghostwriter/cover-letter flow reused as proposal drafting, and a `kind` field (job | contract | freelance) with rate and duration columns in the ledger. Real freelance sources (e.g. Upwork, Contra, Malt, Freelancer.com) need separate evaluation against ToS before adding; many forbid automation, so use alert emails and manual browse only.
9. **Prompt regression evals** (jobsync `evals/` promptfoo) once we add scoring prompts, so changes do not silently shift scores.
10. **Resume audit** with the jobsync review rubric as a one-off per variant, particularly its ATS compatibility section.

Skip: tracer links (needs public host, may look odd), challenge-viewer (conflicts with our no-CAPTCHA rule), SaaS auth/billing, Docker packaging, in-app chat UI, sponsor registers unless a tenant needs sponsorship in UK/NL/CA/US.

## Risks
- **Licence, jobsync:** MIT (`LICENSE`). Copying code or prompts is fine with the copyright notice kept. Lowest risk.
- **Licence, job-ops:** GitHub shows NOASSERTION because `LICENSE` is a composite. The file starts with the **Commons Clause v1.0** condition (no right to "Sell", defined to include fees for hosting or consulting/support whose value derives substantially from the software) followed by the full **GNU AGPL-3.0** text; header line "Software: JobOps / License: GNU Affero General Public License v3.0 / Licensor: JobOps contributors". Net effect: source-available, not OSI open source. Copying code into our MIT repo would force AGPL-3.0 on the combined work and add the no-sell restriction, which conflicts with our MIT `LICENSE`. **Treat job-ops as ideas-only: re-implement from the documented behaviour, do not copy code, prompt text verbatim, or its sponsor-provider code.** The sponsor register data themselves are public government data and can be fetched on our own. Their prompts quoted above are for analysis only.
- **Fragile parts:** scrapers for LinkedIn/Indeed/Glassdoor (JobSpy), Hiring Cafe (needs a headless browser plus challenge viewer), Gradcracker, Khamsat HTML selectors, and FreeHire (no documented rate limit or SLA, per its own docs). jobsync ATS board lists (`companies.json`) will contain dead slugs. job-ops ships `extractors/*` that hit third parties with a spoofed-looking UA (`Mozilla/5.0 (compatible; JobOps/1.0)` in `extractors/fiveamsat/src/*.ts`).
- **ToS:** scraping LinkedIn, Indeed, Glassdoor and Seek violates their terms and risks account or IP blocks; job-ops itself says auto-apply gets people blacklisted, and automates only discovery. Greenhouse/Lever/Ashby public board JSON endpoints are intended public APIs. Freelance marketplaces commonly prohibit automation and scraping.
- **Unauthenticated endpoints:** job-ops OJCP MCP endpoint is unauthenticated by design and forwards queries to FreeHire; jobsync MCP uses bearer tokens but its README recommends `--allow-http` for LAN, which sends tokens in cleartext. We should not expose either.
- **Third-party content as instructions:** both feed scraped postings to LLMs. jobsync explicitly treats pasted postings as untrusted; job-ops does not state this in the files read. Our existing rule (page content is data) already covers it.
- **Cost and drift:** job-ops default scoring rubric weights "career growth" and "industry" generically and appends instructions from settings; a score without our REQUIREMENTS hard rules would be misleading. Hard rules must stay as pass/fail gates, and the score only ranks.

## GAP lines (no engine files touched; to be filed in the backlog by the caller)

Acceptance: `fit_score`, `fit_reason`, `desc_quality` columns plus scoring step in the review loop, provisional when description is a stub.

- GAP: no applied-duplicate detection across reposted roles with new ids (`tools/coverage.py` matches id and company+title only, no similarity threshold or date window).
- GAP: follow-up routing (`log_outcome.py`, `follow-up.md`) has no confidence tiers (auto / review / ignore) for matching an email to an application.

- GAP (licence hygiene): job-ops is AGPL-3.0 plus Commons Clause; copying any code or verbatim prompts into this MIT repo would be a licence breach. Record a "ideas only, no copying" note in `docs/` before anyone adopts from it.
