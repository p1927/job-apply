# career-ops vs job-apply: feature survey (read-only)

Surveyed: /Users/pratyush.mishra/Documents/GitHub/career-ops v1.37.0 (MIT, (c) 2026 Santiago Fernandez de Valderrama). Roughly 150 root .mjs scripts, 681 test files, 112 providers, 11 registry plugins, 60+ modes in 19 languages, Go TUI dashboard. Nothing was run or installed. Method: read headers and docs, not every line; "how it works" lines come from file headers and mode docs, so treat edge-case behaviour as unverified.

Our engine (for comparison): ~3,700 lines of Python in tools/ (ledger_set, coverage, search_boards for Greenhouse/Ashby/Lever, linkedin_harvest.js, record_application, log_outcome, make_resumes, dashboard, check_leaks, tenant isolation, find_answer/learn_answer), plus skills (job-search, setup, ats-playbook). Browser-driven (BrowserOS neo), submits under per-tenant approval mode. Scoring is rule pass/fail against REQUIREMENTS.md, no numeric score. Statuses: New / Relevant / Not-relevant / Applied / Closed.

Value column is for a job seeker who also wants freelance/contract gigs. career-ops has almost no freelance support (grep: "freelance/contractor/b2b" appear only in oferta-signals 16/20/21, offer-prep and apply modes as red-flag text, never as a gig-search or proposal workflow). So "value" for gigs is mostly about generic infrastructure that could be pointed at gig boards.

## Best ideas (5 sentences)

1. Liveness ladder plus repost detection (liveness-api.mjs, detect-reposts.mjs) is the most transferable engineering: a cheap per-ATS API check with a "conservative, return unknown rather than guess" rule keeps us from applying to dead or ghost roles, and it is plain HTTP so a Python port is small. 2. The Block G legitimacy signals (modes/_shared.md, modes/oferta-signals/) are mostly text, already written around fake-recruiter malware take-homes, candidate-paid fees, unpaid placements and agency licensing, and they matter more for freelance and contract work than for permanent roles. 3. Two-pass triage with a compact profile brief (modes/triage.md, _brief.template.md) would cut token cost on LinkedIn harvests, and the Machine Summary plus append-only status-log.tsv would give us funnel and follow-up analytics (funnel-velocity.mjs, followup-cadence.mjs, calibrate.mjs) that our dashboard currently lacks. 4. verify-cv-facts.mjs and story-provenance-check.mjs automate our non-negotiable "only facts in the profile" rule, and negotiation-roi.mjs applies the same gate to rate talk, which is directly useful for contract day rates. 5. Public-API providers (platsbanken, teamtailor, workday, smartrecruiters, personio, hackernews, remoteok, remotive, himalayas) give ToS-clean discovery for Sweden and remote gigs; for actual freelance marketplaces (Upwork, Toptal, Malt, Contra) career-ops has nothing, so that part would be new work for us either way.

## Risks

- Direction mismatch: career-ops never submits (AGENTS.md: "NEVER submit an application without the user reviewing it"); we submit under standing approval. Anything we adopt must keep our rules (no accounts, no CAPTCHA, tenant isolation). Its tracker (applications.md) conflicts with our ledger; docs/CAREER-OPS.md already says we skip it.
- Scraping and ToS: LEGAL_DISCLAIMER.md and README.md line 673 put ToS compliance on the user, with an indemnity clause. It tells agents not to retry LinkedIn through guest endpoints or anti-bot workarounds (AGENTS.md LinkedIn JD loading guard). Providers that hit unofficial endpoints (Workday cxs, Phenom, Oracle, Alibaba/Tencent/Meituan, telegram-channel, feishu-jobs) are fragile and may breach ToS. Prefer official APIs (Platsbanken, Greenhouse/Lever/Ashby public boards, RemoteOK with link-back note per providers/remoteok.mjs).
- Fragility: closure-phrase matching depends on wording per ATS and language (liveness-core.mjs comments describe silent misses from curly apostrophes); iframe-embedded boards defeat simple fetches; 112 providers means constant upstream breakage (the repo has 681 tests largely to manage this). Adopt a few providers, not all.
- Licence: MIT, so code can be copied with the copyright notice kept. offer-prep.md is adapted from Anthropic claude-for-legal (Apache-2.0); keep attribution if copied. plugins-registry entries point to third-party repos pinned by sha (e.g. Schlaflied/career-ops-plugin-linkedin-alerts); each has its own licence and was not audited here. TRADEMARK.md and SIGNATURES.md exist: do not reuse the name or branding.
- Supply chain and size: node_modules, package-lock and a Go dashboard are present; our engine is Python-only. Porting logic is safer than running its Node code, and the owner rule "Claude installs everything" would make a Node dependency our maintenance burden. Fork p1927/career-ops auto-update (update-system.mjs) could pull unreviewed upstream changes.
- Freelance gap: no gig-specific model (day rate, SOW, proposal, client vetting, invoicing, tax). Block G helps vet clients but the rest would be built by us.

## GAP lines

GAP: docs/CAREER-OPS.md claims reuse of scan.mjs, check-liveness.mjs, followup and reply watching, but the engine has no tool that calls them and no test; a stale integration claim (evidence: tools/ has only sync_career_ops.sh).
GAP: our ledger has no append-only status-transition history (from/to/date/source), so time-in-stage and response-latency cannot be computed; career-ops status-log.tsv shows the shape.
GAP: no automated check that resume or answer text contains only facts from candidate-profile.md; non-negotiable 1 relies on agent discipline (career-ops verify-cv-facts.mjs is the model).
GAP: no liveness check before applying; ledger Closed is set only by hand after "Job not found", so dead roles can burn an application slot.
GAP: no posting-legitimacy screen (fake recruiter, candidate-paid fee, unpaid trial work) in job-search/SKILL.md; matters most for contract and gig leads.
GAP: ledger vocabulary has reason code `contract` as a rejection reason (config/vocab.json), so a tenant who also wants contract gigs would have them auto-dropped; needs a per-tenant override or a separate gig track.
GAP: README says Greenhouse, Ashby and Lever only; no Workday, Teamtailor, SmartRecruiters, Personio providers although several Nordic employers in the skill (Teamtailor forms) use them.
GAP (career-ops, fork risk): update-system.mjs can pull upstream changes into the fork checkout; the engine should pin a commit and review diffs before running anything from it.
